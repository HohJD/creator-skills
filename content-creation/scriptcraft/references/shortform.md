# Short-form AI tutorial (15–90 seconds)

## Editorial model

**0–3s** surprising *visible* artifact, problem or question (not a mandatory fixed time)
**3–8s** concise identity of task and what I tried
**8–35s** minimal replicable path, one action per visual beat
**35–50s** proof and practical caveat where applicable
**last 3–7s** relevant CTA (or useful final lesson)

These are flexible planning cues, *not* engagement guarantees. A 20-second video should collapse setup/steps, not read the 60-second plan faster.

## Scene design

For each beat write: time estimate, shot (phone/tablet/browser/recording), *exact* visible action, voiceover, overlay text <= one short sentence, proof or limitation. Use jump cuts only when they don't hide critical steps. If setup is long, film an overview and link the full guide rather than pretend the build is one tap.

## Default form: reveal → test → steps → payoff → CTA

- Reveal final artifact with legible visual.
- Acknowledge AI/simulation status when a result could be mistaken for real product footage.
- Name tool late enough for the output to land, but early enough to teach.
- Show input and output where possible; keep a single primary action in each shot.
- On-screen labels assist comprehension; voiceover need not read every label verbatim.
- Preserve the exact provided CTA when relevant: comments, link, template, prompt, repository.

## When audience can't reproduce in 30 seconds

Choose one: show *a single step*, show the output and promise a longer guide, or raise the duration. Do not silently omit a mandatory install/verification step while claiming it is easy or instant.

## Platform reminders

Instagram/TikTok/Reels: vertical framing, readable UI crops, captions avoiding UI-covered areas. XHS: colloquial Chinese, concrete saveable takeaway, plain CTA. YouTube Shorts: more value-first than artificially looped endings. Validate any platform-specific requirements from current documentation; do not invent platform rules.
