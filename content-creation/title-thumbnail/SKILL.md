# Video titles and thumbnails

Write down the payoff a viewer actually gets and where the footage delivers it. Use the intended audience and discovery surface. When offering alternatives, vary the viewer's reason to click: the task they searched for, an unresolved decision, or a visible outcome. Honor requests for one strong pair.

Give each pair a publishable title, thumbnail composition, exact overlay text if useful, and the frame or asset needed. The title can name the task while the image shows what is at stake. Frame the subject so the key detail survives at small size. If the image is evidence, use a real frame or specify the shot to capture. Keep any generated illustration recognisably illustrative. Do not simulate a real interface, reaction, result, endorsement or benchmark as proof.

Read the pair cold. Could a viewer predict the subject? Could they reasonably expect something this video never delivers? Make the promise narrower if needed. If comparing versions after release, record what changed and use comparable traffic sources and windows.

## Try it

> Give me a search-led and a browse-led title/thumbnail pair for [video]. The actual payoff is [result] at [moment]. Specify which real frame to use and keep any overlay short.

## Worked example

Fictional footage: a maker lights the same bowl from the front and from the side. Only the side-lit clip shows the stamped rim clearly.

**Search-led title:** How to light a stamped ceramic rim. **Thumbnail:** Match the bowl size in both real frames, with the stamp in the same position. Label the frames “Front” and “Side”.

**Browse-led title:** Where did the pattern on this bowl go? **Thumbnail:** Use the side-lit rim as a large crop and a small inset of the flat-looking frame. The two frames supply the answer in the video.
