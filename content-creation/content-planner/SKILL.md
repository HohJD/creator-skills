# Editorial planning

Start with the audience's actual question or task. Use comments, search queries or support notes when available. Keep assumptions visible if the brief supplies only a theme. Do not claim a trend, posting frequency or best time without supporting data.

Separate ideas from commitments. For each scheduled piece, identify its reader payoff, format, required source or asset, production effort and the person or dependency that can block it. Work backward from hard dates. Use relative slots when dates or time zones are missing. Put capture before editing and allow review before publication if the brief requires it.

Check the hours in each window, including setup and revision. Label estimates and leave optional work in a backlog. Reuse one shoot for related pieces only if each piece does a different job. Give the smallest useful schedule plus a swap if an important asset arrives late. A calendar request produces a draft schedule unless the user separately asks to schedule posts.

## Try it

> Plan [period] of content from [questions/assets]. I have [hours per week] and [hard deadline]. Show estimated time, dependencies, purpose and what to drop if the shoot slips.

## Worked example

Fictional week: 180 minutes, one wheel demonstration on Tuesday, two reader questions about centring clay.

| Window | Work | Estimated minutes |
| --- | --- | ---: |
| Monday | Pick the question and rehearse the overhead framing. | 25 |
| Tuesday | Record one attempt and a close view of the wobble. | 45 |
| Wednesday | Cut and caption the demonstration. | 70 |
| Thursday | Check the cut, then draft a still post showing where to look. | 30 |
| Reserve | Fix an unreadable shot or move the still post to next week. | 10 |

If Tuesday is cancelled, move the video. Use a previously cleared photo for a short Q&A only if it shows the point being discussed.
