# Livestream run of show

Establish the hard start and finish, timezone where it matters, audience promise, available operators, guest windows and sections that may be dropped. Plan preflight outside the public programme unless it consumes part of the booked slot. Include preview and audio checks the crew can actually perform.

Produce clock time or elapsed in/out, duration, responsible person, what goes on screen and the host's transition. Count handoffs and the closing line. Sum every live interval and check it fits the hard end. If the guest arrives late, the demo fails or questions run long, specify what to swap or cut and give the new timing. A fallback must work with the assets and people present. Do not invent a backup operator, prerecorded clip or platform feature.

For a solo creator, use simple state changes. Label private production cues separately from anything the host should say out loud. The request is for a rundown unless broadcasting or scheduling was explicitly requested.

## Copyable brief

> Build a [minutes]-minute live rundown for [demo]. I have [crew/assets] and a hard stop at [time]. Include transitions, a late-guest fallback and a timing check.

## Worked example

**Fictional input.** Solo host, 12 minutes live, guest available from minute 3, one real sample and no backup video. Must keep one minute for closing.

| Elapsed | Host and screen |
| --- | --- |
| 0–3 | Welcome, show the sample and name the viewer's question. |
| 3–7 | Bring guest in. Ask them to point out the sample's distinguishing feature. |
| 7–10 | Host shows the detail again and answers one viewer question. |
| 10–11 | Recap the answer with the sample in frame. |
| 11–12 | Close and sign off. |

If the guest arrives at minute 5, use 3–5 for the sample detail, 5–9 for the guest, 9–10 for the question, then keep the original recap and close. Total in both paths: 12 minutes.
